# S 弯重复启动改动

已完成软件测试与脚本部署；助手未启动实车或发送运动目标。

## 原因

- 旧命令每轮都重新启动传感器、Cartographer、完整 Nav2，结束后又全部关闭。
- 2026-09-27 14:49 的日志中，planner_server 配置从约 14:49:18 到 14:49:34，单这一阶段约 16 秒。S 弯直接给 FollowPath 一条参考路径，并不需要重新执行全局规划。
- 原流程额外固定等待定位 3 秒、记录器 3 秒、发车倒计时 5 秒。
- 每次结束都会保持急停锁存，而原启动流程只报告需要复位，没有完成下一轮的复位流程。

## 使用

每次运行下面相同的命令，只跑一轮，不会自动无限循环：

```bash
bash ~/racecar-tests/s-curve-test/run_s_curve.sh --allow-unknown-map
```

第一轮启动硬件和定位。之后保留本工具启动的后台进程，车停在急停锁存状态；新命令取消遗留目标、等上一轮速度指令结束、准备记录和路径，再调用现有驱动复位服务发起这一轮。

每次路径仍以该轮开始时的车身位置和朝向构建。需要从同一起点比较时，先将车放回同一起点与朝向，再执行命令。

`Ctrl+C` 停止当前这一轮并保留定位后台。结束当天测试，或需要改用键盘/其他导航入口时：

```bash
bash ~/racecar-tests/s-curve-test/run_s_curve.sh --stop-stack
```

需要重新建立定位，可执行：

```bash
bash ~/racecar-tests/s-curve-test/run_s_curve.sh --allow-unknown-map --restart-stack
```

`--countdown 5` 可恢复 5 秒倒计时；默认 1 秒。`--preflight-only` 只准备，不复位发车。`--shutdown-after-run` 恢复每轮结束后关闭后台。

## 实现边界

- 新增 FollowPath 专用导航启动分支，共用原 driver_calibration.yaml、nav_carto.yaml，不另存运动参数。普通探索入口默认继续启动完整 Nav2。
- 目标 0.35 m/s、起步加速度 0.50 m/s²、PWM 上限 1600、闭环参数未改动。
- 检测共享配置变化时，下一轮停止本工具的旧后台并重新加载配置。
- 不删除急停文件，不关闭驱动超时或制动。只在用户新执行一轮命令时复位一次。准备或运行中出现新急停，则中止这一轮，不自动重试。
- 不接管其他工具启动的节点；记录 PID、系统启动标识和进程启动时间，避免误杀已复用的 PID。
- 地图策略和现有碰撞设置保持原样；路径记录、闭环状态记录仍保留。记录器提供 ready.json，代替固定等待。
- 每轮仍有独立的 runs 目录；events.jsonl 保存阶段耗时；startup_seconds 保存从启动脚本到目标接受的时间；stack.log 保存本轮后台日志片段，stack_source.json 指向完整后台日志。
- 结束后的离线分析降为后台低优先级，不阻塞下一次命令。

## 验证

使用模拟 ROS 服务/动作运行真实 run_session.py，覆盖连续两轮复用、配置变化重启、准备期间急停、拒绝复位、取消失败、参数不一致、只准备、后台关闭、遗留目标取消。

Linux 进程所有权测试只启动休眠 Python 进程，覆盖正常复用关闭、PID 复用、系统重启记录以及非本工具进程拒绝接管。

新 Nav2 启动描述在电脑 ROS Humble 环境完成构造检查，没有执行任何节点。真实硬件的首次启动耗时、后续启动耗时及运动效果尚未测量。
